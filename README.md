# ตลาดขนมหวาน (ออนไลน์: ไอดี · เซฟบนเซิร์ฟเวอร์ · แรงกิ้ง · เพื่อน)

โครงสร้าง: `server.js` (Node ไม่มี framework) + `public/index.html` (หน้าเกม) + Postgres

## ดีพลอยบน Render (แบบ Blueprint)
1. อัปโหลดโฟลเดอร์นี้ขึ้น GitHub (ให้ `render.yaml` อยู่ที่ราก repo)
2. Render → New → Blueprint → เลือก repo → Apply
   จะสร้างทั้ง Web Service และ Postgres ให้ แล้วต่อ `DATABASE_URL` ให้อัตโนมัติ

ทำเองแบบไม่ใช้ Blueprint: สร้าง Postgres ก่อน แล้วสร้าง Web Service
(Build: `npm install`, Start: `node server.js`) แล้วใส่ env `DATABASE_URL` เป็น Internal Database URL

## รันในเครื่อง
    npm install
    node server.js        # ไม่ตั้ง DATABASE_URL = เก็บลงไฟล์ data.json (ใช้ทดสอบเท่านั้น)
เปิด http://localhost:3000

## ข้อควรรู้ (แพ็กเกจฟรีของ Render)
- Postgres ฟรีหมดอายุ 30 วันหลังสร้าง (มีเวลาอัปเกรดอีก 14 วัน ไม่งั้นข้อมูลถูกลบ)
- Web Service ฟรีจะหลับหลังไม่มีคนเข้า 15 นาที ครั้งแรกที่ตื่นใช้เวลาราว 1 นาที

## เวอร์ชัน (รูปแบบ 00.0000) และรายละเอียดอัปเดต
- เลข 2 ตัวหน้า (`00`) = อัปเดตขนาดใหญ่ เช่น เพิ่มระบบหรือฟีเจอร์ใหญ่
- เลข 4 ตัวหลัง (`0000`) = อัปเดตขนาดเล็ก เช่น แก้บั๊ก ปรับเล็กน้อย
- อัปเดตใหญ่ → เลข 2 ตัวหน้า +1 และเลข 4 ตัวหลังเริ่มที่ `0001` ใหม่
- เริ่มนับใหม่ที่ `01.0001` (รายการอัปเดตก่อนหน้าที่เป็นรูปแบบเก่ายังเก็บไว้ในเกม)

เลขเวอร์ชันแสดงต่อท้ายชื่อเกม (เช่น `Ver 01.0001`) แตะเพื่อดูรายละเอียดการอัปเดตในเกม
เก็บอยู่ในบล็อก `BUILD` ของ `public/index.html` (ระหว่าง `/*BUILD_START*/` และ `/*BUILD_END*/`)

    npm run watch                  # เปิดทิ้งไว้ บันทึกไฟล์ทีไร เลข 4 ตัวหลัง +1 อัตโนมัติ
    npm run bump -- "แก้บั๊ก X"     # อัปเดตเล็ก: เลข 4 ตัวหลัง +1 และเพิ่มหัวข้ออัปเดต
    node bump.js --major "ปรับระบบใหม่"    # อัปเดตใหญ่: เลข 2 ตัวหน้า +1

## ระบบชื่อเล่น
หลังสมัครไอดีเสร็จ เกมจะให้ตั้งชื่อเล่น (2–16 ตัวอักษร ห้ามซ้ำกัน) ใช้แสดงในกระดานผู้เล่น แตะชื่อผู้เล่นด้านบนเพื่อเปลี่ยนภายหลัง
ฐานข้อมูล Postgres จะเพิ่มคอลัมน์ `nick`, `nick_key` ให้เองตอนเซิร์ฟเวอร์เริ่มทำงาน

## เพื่อน จดหมาย ของขวัญ (เวอร์ชัน 01.01.x)
- เพิ่มเพื่อน = ส่งคำขอ อีกฝ่ายต้องกดยอมรับในจดหมาย (ถ้าอีกฝ่ายส่งคำขอมาก่อน จะเป็นเพื่อนกันทันที)
- จุดเขียวหลังชื่อ = ออนไลน์ (เซิร์ฟเวอร์บันทึก `seen` ทุกครั้งที่ผู้เล่นเรียก API; ออนไลน์ถ้าเห็นภายใน 2 นาที)
- ส่งของขวัญ: หัวใจ 1, เหรียญ 10/25/50 หรือตัวช่วย 1 ชิ้น ส่งได้ 5 ชิ้นต่อเพื่อนต่อวัน (รวม 20 ชิ้นต่อวัน) ผู้ส่งเสียของเอง ผู้รับกดรับในจดหมาย
- ตารางใหม่ใน Postgres (สร้างเองตอนเริ่มเซิร์ฟเวอร์): `friend_requests`, `mail` และคอลัมน์ `users.seen`
- API ใหม่: `POST /api/friends` (ส่งคำขอ), `/api/friends/accept`, `/api/friends/decline`, `GET /api/mailbox`, `GET /api/ping`, `POST /api/mail/send`, `POST /api/mail/:id/claim`, `POST /api/mail/:id/read`, `DELETE /api/mail/:id`
- เพื่อนเดิมที่เพิ่มไว้ก่อนมีระบบตอบรับ (เป็นเพื่อนฝั่งเดียว) จะยังเห็นอยู่ แต่ส่งของขวัญได้เมื่อเป็นเพื่อนกันทั้งสองฝั่งเท่านั้น

## กันเซิร์ฟเวอร์หลับ (Render แพ็กเกจฟรี)
- `server.js` ยิง `/api/health` ใส่ตัวเองทุก 10 นาที (ใช้ตัวแปร `RENDER_EXTERNAL_URL` ที่ Render ตั้งให้เอง)
- `.github/workflows/keepalive.yml` ให้ GitHub ยิงปลุกทุก 10 นาทีเป็นตัวสำรอง (แก้ `GAME_URL` ในไฟล์ให้เป็นที่อยู่ Render ของคุณ)

## ย้ายฐานข้อมูลไป Neon (Postgres ฟรีของ Render หมดอายุ 30 วัน)
1. สมัคร neon.com สร้างโปรเจกต์ (เลือกเวอร์ชัน Postgres ไม่ต่ำกว่าฐานข้อมูล Render เดิม) แล้วคัดลอก connection string
2. GitHub → Settings → Secrets and variables → Actions → เพิ่ม Secret 2 ตัว: `OLD_DATABASE_URL` (External Database URL จากหน้า Postgres บน Render) และ `NEW_DATABASE_URL` (จาก Neon)
3. อัปโหลด `server.js` ตัวใหม่ และ `.github/workflows/migrate-db.yml` แล้วเปิดแท็บ Actions → migrate-db → Run workflow
4. ดูท้ายล็อก ตารางและจำนวนแถวของ OLD กับ NEW ต้องตรงกัน (ขั้นตอนนี้อ่านฐานข้อมูลเดิมอย่างเดียว ไม่ลบอะไร)
5. Render → เว็บเซิร์ฟเวอร์ → Environment → แก้ `DATABASE_URL` เป็น connection string ของ Neon (ถ้ามีข้อความ `channel_binding=require` ต่อท้าย และเชื่อมต่อไม่ได้ ให้ตัดส่วนนั้นออก) แล้วรอดีพลอยใหม่
6. ทดสอบล็อกอินในเกม ยืนยันว่าเซฟยังอยู่ แล้วค่อยลบฐานข้อมูลเก่า (หรือปล่อยให้หมดอายุเอง)
- `render.neon.yaml` ใช้หลังย้ายเสร็จเท่านั้น: ลบ `render.yaml` เดิม แล้วเปลี่ยนชื่อไฟล์นี้เป็น `render.yaml` (ไม่มีส่วนฐานข้อมูล และ `DATABASE_URL` ตั้งเองในแดชบอร์ด)
